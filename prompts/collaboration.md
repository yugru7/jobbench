# AI 协作规则 —— prompts/collaboration.md

> 给 AI agent 用：讲「**AI 怎么跟这个工作台协作、自动化任务里该干什么**」。
> 先读仓库根目录的 `AGENTS.md`（铁律 + 接口速查，已作为工作区规则注入）；要跑**定时/批量**任务时，再读 `prompts/automation.md`（完整 runbook）。
> 本工作台是一个**本地运行**的 BOSS直聘 岗位筛选 / 投递工具（面板 `http://127.0.0.1:7788`）。

## 1. 分工模型（最重要的一条）

| 谁 | 干什么 |
|---|---|
| **工具（机械部分）** | 爬取岗位、读 JD 和招聘者活跃度、把招呼语**填进输入框**、发送（受护栏约束） |
| **你（智能部分）** | 补全用户知识库、逐条评判岗位匹配度并勾选、按 JD 写定制招呼语、决定采集节奏与来源组合 |

不要把这活当成"调一个接口就完事"。工具只提供机械动作，**判断始终是你的**，所以你的输出质量取决于是否真的读了 `knowledge.json` 和 JD 原文。

## 2. 红线（永不越界）

1. **默认只填不发**。接口默认 `fillOnly`（只把招呼语填进输入框、绝不点发送键）。`confirm` 会**真的逐条发给 HR**，只有在用户**明确授权**后才可用。`mode:"auto"` **永不调用**（服务端强制 `userApproved:true`，agent 传了也是 403）。
2. **只写真实信息**。知识库 / 招呼语里的每个字都会发给真人 HR，面试可能被追问。只能写知识库里真实记录的、或用户明确授权使用的内容，**禁编造经历/技能/数字**；对话里的零散信息要先问用户是否入知识库，别直接写进招呼语。
3. **一律走 HTTP API `http://127.0.0.1:7788`**，不要用命令行跑 `greet.js`（面板看不到进度、还会抢浏览器锁）。服务端只受理本机来源（Host/Origin 白名单）。
4. **写回类接口（`/api/knowledge`、`/api/config`、`/api/prompt`）body 绝不能带 BOM**（带了会**静默清空用户数据**，且照样返回 `ok`），调完**必须 GET 回读核对**。用 Node `fetch`+`JSON.stringify` 最安全。

## 3. 工具面（agent 能用的接口）

- 读：`GET /api/bootstrap`（首屏全量）、`GET /api/collected`（候选池，含 `checked`）、`GET /api/config`、`GET /api/knowledge`、`GET /api/prompt`、`GET /api/records`
- 采集：`POST /api/collect`（`source: search|recommend|expect`）、`POST /api/expects`（读意向方向）
- 勾选 / 招呼语：`POST /api/checked`、`POST /api/greetings`
- 发送：`POST /api/send`（**仅** `fillOnly`，或用户明确授权后的 `confirm`）
- 运维：`POST /api/stop|pause|resume|close-browser`、`POST /api/collected/delete|clear-sent|clear`
- 写回（改前先经用户确认、改后回读）：`POST /api/knowledge|config|prompt`

## 4. 开跑前必问清单（用户一提"弄个自动化/定时任务"就先问齐）

本文档与 `prompts/automation.md` 是**通用模板**，但每个用户的个性化维度不同。**用户要做自动化时，先把下面这张表一次问清**（同一条消息批量问，别挤牙膏），拿到答复再建任务 —— **不许带着疑问操作，也不许边跑边问**。缺失项不许自己拍板。

| # | 维度 | 要问什么 | 常见默认（只作建议，别替他决定） |
|---|---|---|---|
| 1 | 目标城市 | 投哪个城市？要不要多城市？ | 沿用 `config.cityName` |
| 2 | 关键词/方向 | 沿用 `config.keywords`，还是本任务换/加？ | 沿用 config |
| 3 | 来源组合 | `search`/`recommend`/`expect` 各跑几个？ | search 4 + recommend 3 + expect 3 |
| 4 | 经验档位 | 在校应届 / 不限 / 其它？ | 实习投递 = `108` |
| 5 | 岗位性质 | 只实习 / 实习+全职 / 只全职？ | 只实习 |
| 6 | 硬性筛选 | 活跃度要求（刚刚·今日·本周）、双休、薪资下限、公司规模、行业 | 最近活跃优先 |
| 7 | 排除项 | 哪些方向/公司/关键词直接不勾？ | 沿用 `config.excludeKeywords` + 主线外方向 |
| 8 | 匹配宽松度 | 海投（沾边就勾）/ 精选（宁缺毋滥）？ | 海投 |
| 9 | 数量与额度 | 本轮**目标总量**（例 10 / 30 / 100）、每轮岗位数、每日采集上限、每日发送上限 | `maxJobsPerRun` / `dailyCollectCap` / `dailyCap` |
| 10 | 发送模式 | `fillOnly`（只填不发、用户自己点发）/ `confirm`（无人直发） | `fillOnly` |
| 11 | 招呼语是否过目 | 发送前是否要让用户先看招呼语？ | 要过目 |
| 12 | 调度 | 几点跑、多久一次（cron 5 字段；一次性定点不支持） | 待定 |
| 13 | 报告 | 要哪些内容、只回对话还是也落文件？ | 只回对话 |

补充规则：
- **动手前先 `GET /api/config`**，把现有默认值摆给用户，逐项确认"沿用默认"还是"本任务覆盖"。
- 选 `confirm` 必须拿到用户"**已授权无人直发、招呼语不用过目**"的明确答复，否则退回 `fillOnly`。
- 涉及改 `config`（城市/关键词/额度/排除词）的项：先经用户确认再改，改完按 `AGENTS.md` 铁律 5 回读核对。
- expect 源的城市（意向页签后缀）≠ 目标城市时，让用户决定：改 BOSS 简历期望城市，还是本轮不跑 expect。
- 问齐后建议先跑一轮**小批量 `fillOnly` 探测实验**验证链路，再正式建定时任务。

## 5. 自动化任务该做什么（规模自适应的流水线）

无人值守（定时/批量）时按 `prompts/automation.md` 执行；这里给出骨架。**流程不写死**：量小（目标 ≤ 单次上限）时每个阶段就是一轮；**量大（例目标 100）时必须把「采集」与后面的「筛选 / 写招呼语 / 发送」解耦** —— 先分批连采到够，再**统一**筛，再分批写、分批发。

**0 前置检查** → 服务在跑？登录态在？今日额度还有？（任一不满足就停，别硬跑）

**1 采集（三来源都用，别只跑 search；量大时循环到够）**
- 开跑前先跟用户定「本轮目标总量」；单次采集量受 `config.maxJobsPerRun` 与硬上限约束，目标更大时要**分批连采**：每轮取 `min(剩余, maxJobsPerRun)` 名额，再按来源分配。
- `search`：`keywords` 取自 `config.keywords`，按面板城市定位。
- `recommend`：无关键词，**噪声大**，靠 `config.excludeKeywords` 拦 + 跑完复看剔非技术岗。
- `expect`：先 `POST /api/expects {force:true}` 读**真实**方向，再按 `expectTab` 采集。⚠️ **城市硬约束**：expect 岗位来自 BOSS 简历期望城市，采集端用城市参数过滤；页签城市 ≠ 目标城市时结果会被**全数丢弃** —— 不一致就别跑 expect（或让用户去 BOSS 改简历期望城市）。
- 经验档位用 `config.experience`（实习投递 = `108` 在校/应届）。
- **数量约束别当固定常量**：`maxJobsPerRun` / `dailyCollectCap` / `dailyCap` 及服务端硬钳制（超上限静默压回）**都以实际 `config` 为准**。
- **每批之间必须 `waitIdle`**（单实例锁），别并发触发。

**2 统一筛选（等全部采集完成后一次性做）**
- 面板「二次筛选」是**纯前端**逻辑，无人值守时没人点控件 → 你在本地复刻判据（数据都在 `GET /api/collected`）：实习判定（标题或 JD 含 `实习|见习|应届|在校|校招`，**复刻时补上英文 `Intern|Internship`**）、活跃度（`hot`=刚刚/今日，`mid` 再加 3日内/本周）、双休（`daysPerWeek` 1–5 有、≥6 无、0 不算）、薪资下限（月薪折日薪 `/22`，解析不出不受限）、公司规模（精确档）、行业（子串）。
- AI 匹配以 `knowledge.json` 为标尺，逐条比对 JD。**分级策略（海投）**：明显不匹配才排除，**沾边就勾**，宁多勾让用户划掉，别替用户把门。
- 勾选结果**一次性写回** `POST /api/checked {urls:[...]}`；只处理 `checked:false` 且无 `sent` 的岗位。

**3 写招呼语（可分批，每批 N 条）** → 读 `prompts/greeting.md`（**以文件最新为准**），只为**已勾选**岗位写，逐条对齐 JD、≤130 字符、两条调换还能用即不合格；写回 `POST /api/greetings`。分批只为控 body 体积、缩小失败影响面，**批间不需 waitIdle**。

**4 发送（可分批）** → `items` 取自已勾选岗位，`mode` 默认 `fillOnly`；无人值守且用户已授权时才用 `confirm`。护栏：单次硬上限（**以实际 config 为准**）+ 按今日剩余额度截断；量大时分批发，**批间 `waitIdle`**。

**5 报告** → 各来源新增数 / 勾选数 / 招呼语数 / 发送成功·失败·跳过数 / 今日已用与上限 / 跳过原因。

## 6. 决策策略（别过度保守，也别把关）

- **匹配度**：优先活跃度高的（刚刚/今日活跃），JD 硬条件（到岗时间、每周天数、实习时长）与用户真实情况对照；薪资离谱 / 行业岗位性质冲突 / 只要全职 才算明显不匹配。
- **排除项**：用户在对话里明确点名排除过的方向必须遵守；与**用户求职主线**明显跑偏的方向主动剔（主线由用户在开跑前确认，例：纯 PHP、算法研发、嵌入式硬件、数据标注、AI 漫剧、安服）。
- **招呼语**：开篇前 15 字甩最硬的相关经验，禁礼貌废话，见 `prompts/greeting.md` 的红线与骨架。

## 7. 硬约束 / 已知坑（记住，别当 bug 报）

- expect 城市冲突（见 §5.1）、recommend 噪声大、前端筛选是纯前端（需自建判据）—— 这是设计现状，不是故障。
- 面板任务走 **CDP 常驻浏览器**：复用同一个 Chrome + 同一标签页，每轮原地翻页 → 上一轮「只填不发」的输入框内容会被下一轮**冲掉**；要用窗口手动补发，就先把这一批发完再开下一轮。
- **「手动发送」识别窗口约 30 分钟**：脚本退出后再点发送不会被标 `sent`，岗位仍留在表里（隐藏 ≠ 删除）。
- 「已有任务在跑（pid xxx）」多半是上一任务的残留进程，先确认它是否已干完活，别硬重试。

**ⓐ expect 页签是「逐字全等」匹配，且缓存会过期 —— 跑 expect 前必须先刷方向**
- 现象：`POST /api/collect {source:"expect", expectTab:"某方向(某市)"}` 返回 `{"ok":true}` 但秒回 idle、新增 0；日志 `WARN 页签「某方向(某市)」不在你的意向里，终止`。**面板上直接点同名 chip 也一样爬不到**。
- 根因：`lib/collect.js` 里 `all.filter(t => t === EXPECT_TAB)` 是**严格全等、不做括号全/半角归一**；页签名来自 `logs/expects-cache.json`（最后一次真读的快照），而 BOSS 自己渲染的括号**全/半角不统一**（实测同一批里既有全角 `方向（某市）`、也有半角 `方向(某市)`），且新页签不会自动进缓存 → 缓存名字一旦过期，全等必失败、静默返回 0。**面板点 chip 和 agent 传 `expectTab` 是同一条路**（chip 文字 → `/api/collect` 的 `expectTab` → 同一个 `--expect-tab` + 同一次全等比较），所以面板直接点**并不免疫**，它只是多了个「刷新方向」按钮能把缓存刷成真实名字。
- 规避：跑 expect 前先 `POST /api/expects {force:true}`，再从 `logs/expects-cache.json` 的 `tabs` 取真实页签名（别凭记忆写）；或在面板点一下「刷新方向」把 chip 刷成真实名字后再点。

**ⓑ 复刻二筛的「只实习」只认中文词 —— 英文 `Intern` 岗会被误杀**
- 现象：本地复刻 `public/js/render.js` 的 `visibleCands` 过滤后，`xxx Intern(...)` 这类英文命名的实习岗被误筛掉。
- 根因：面板判据匹配 `/实习|见习|应届|在校|校招/`，英文 `Intern/Internship` 命名**不命中**。
- 规避：复刻判据时补上 `Intern|Internship` —— 这是「复刻判据」与「面板判据」的真实差异，别照抄漏项（照抄会比面板多丢岗位）。

**ⓒ 招呼语里任何数字/范围类事实，必须回 `knowledge.json` 的 `entries` 逐条核对 —— `profile.identity` 是概括句，不能当事实源**
- 现象：招呼语写「独立做过两个全栈项目并公网上线」，用户当场指出实际只有一个才是公网上线的全栈项目；已发出的消息**撤不回**，只能靠后续轮次修正。
- 根因：`profile.identity` 是一句**概括**（原话「独立完成过两个全栈项目…公网部署上线的全流程」），把「数量 + 属性」压缩在同一句里，未必与 `entries` 明细一致；照抄这句 = 把概括当事实用。
- 规避：写进招呼语的数字/范围（项目个数、代码行数、实习月数、并发数）都要回 `entries` 找到出处；`profile` 只用来定基调。发现 `profile` 与 `entries` 冲突 → **先问用户、改知识库再用**，别自行取舍。

**ⓓ 内联调 API 时别用 `node -e` 传 JS —— Windows PowerShell 5.1 会把参数里的双引号吃掉**
- 现象：`node -e 'const B="http://127.0.0.1:7788"; ...'`（单引号包裹或 here-string `@'...'@`）直接报 `SyntaxError: Unexpected token ':'`，回显里源码的引号全没了（`const B=http://127.0.0.1:7788;`）—— 看着像我们的代码有 bug，其实是外壳吃引号。
- 根因：PowerShell 5.1 向原生程序（node.exe）传参时会重写/剥离参数中的 `"`，JS 源码里的字符串引号被吞 → 语法错误，与 API/脚本本身无关。
- 规避：**用 PowerShell 原生 `Invoke-RestMethod` 内联调**（无引号问题，只读一次即可）—— GET 直接 `Invoke-RestMethod -Uri 'http://127.0.0.1:7788/api/xxx'`；POST 用 `$p=<hashtable>|ConvertTo-Json -Depth 6 -Compress` 再 `[Text.Encoding]::UTF8.GetBytes($p)` 当 `-Body`（**无 BOM**，中文稳）。实在要跑 JS，就写到 `%TEMP%\` 下的 `.js` 文件再 `node <file>`（跑完删），别贴进命令行。

- 遇到新坑：按上面「现象 / 根因 / 规避」格式补进本节的「已知坑」，**「真实踩过且可能复发」的才记**；`AGENTS.md` 的「常见坑」保留精简版即可（两处不要各写一份长文）。

## 8. 中止条件

被踢登录（`kicked-login`）、今日额度用尽、已有任务在跑、服务未启动 → **立即中止**并把原因写进报告，不要反复重试。
