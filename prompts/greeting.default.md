# 高回复率招呼语生成规则 —— prompts/greeting.md
> 给AI agent用：按这份规则给岗位写招呼语，写完经 `/api/greetings` 写回面板。
> 这份文件是招呼语的单一事实来源，面板「编辑招呼语」页可直接修改，以最新内容为准。

## 核心生成铁律（优先级最高，必须严格遵守）
1. **零礼貌冗余开场**：绝对禁止"您好、看到您发布的岗位、对这个方向很感兴趣、希望获得机会、贵司"这类客套废话，开头第一句直接甩硬货。
2. **前15字黄金位**：开篇前15个字符必须直接抛出和岗位最匹配的核心技能/经历，HR扫一眼就判断是对口候选人，不要把关键词埋在句子中间。
3. **主动打硬性痛点**：如果JD出现"可接受出差、能抗压、能接受加班、外勤驻场、弹性排班"这类硬性要求，必须在话里主动对应适配——直接点明可接受全出差、适应高强度节奏、时间灵活可配合排班，不要等HR后续追问，第一时间打消对方顾虑。
4. **全程精简无套话**：删除所有空泛形容词（吃苦耐劳、学习能力强、踏实认真），每一句话都是HR关心的硬信息，总长度控制在80-120字，绝对不超过130字符（BOSS直聊会自动截断）。

## 话术骨架（按优先级从前到后排，缺素材的段落直接跳过，不要硬凑）
1. 【开篇优势段（前15字核心位）】：直接上和JD最匹配的技能/经历关键词
2. 【匹配经历段】：围绕JD核心要求，写1条最贴合的实践/项目经历，直接命中JD关键词
3. 【痛点适配段】：对应JD里的硬要求（出差、抗压、出勤节奏等），主动给出适配答复
4. 【硬条件段】：从知识库里提取和求职场景匹配的硬条件 —— 在校生写实习时长/每周到岗天数，社招写到岗时间/薪资预期/可接受出差，应届写到岗时间/可接受的工作节奏。只写知识库里真实有的值。
5. 【收尾】：固定用"期待进一步交流。"收尾，不要加问句、不要加客套。

**动词库（按语气强度选，不要吹过头）**：
| 段 | 动词选项 | 约束 |
|---|---|---|
| 技能 | 掌握 / 熟练 / 熟悉 / 了解 | 有完整落地经验用熟练/掌握，做过Demo用熟悉，仅理论认知用了解 |
| 经历 | 做过 / 具备……的实战经验 | 真实完成过的项目才能用"做过" |
| 能力承诺 | 能完成 / 快速上手 / 能 | 对应JD要求的具体能力写 |
| 硬条件 | 按求职场景写知识库真实值（实习时长/到岗时间/薪资预期等） | 不要为了匹配 JD 硬凑数值 |
| 特色 | 擅长 | 写具体的业务落地特点，不要写空泛形容词 |
| 收尾 | 期待进一步交流。 | 固定句号结尾 |

## 经历包装边界
✅ 允许围绕JD关键词，把课程项目、课程作业、自练Demo、相关实践经历往JD方向侧重表述；同一项目根据JD侧重点调整描述，不要罗列多个项目。
❌ 禁止编造和自身身份严重脱节的内容：比如在校生写工作5年全职经验、应届生写主导千万级大厂项目、社招写还在上学 —— 一面试就穿帮。
❌ 实习时长、每周到岗天数这类硬信息必须写知识库里的真实值，不能为了匹配JD硬凑时长。
❌ 每条招呼语只服务当前一条JD，两条调换岗位还能通用 = 不合格。

## 红线（出现任意一条即为废稿）
❌ 禁止任何问候语、自我表达兴趣的铺垫句
❌ 禁止空泛套话：吃苦耐劳、学习能力强、性格开朗、踏实肯干
❌ 禁止问句结尾：请问还招人吗、方便聊聊吗
❌ 禁止把能力关键词埋在句子后半段
❌ 禁止摘抄JD大段原文，只提取关键词自然融入句子
❌ 禁止输出解释、思考过程、引号、JSON代码、备注文字，只输出招呼语正文
❌ 禁止超过130字符，超过必须删冗余套话压缩

## 边界情况处理
- JD内容很短、有效关键词少：基于岗位名称+可迁移通用能力，优先把硬条件（在校生→实习时长/时间灵活性；社招→到岗时间/可适配加班出差）放前面
- JD中英混合或纯英文：招呼语统一用中文写，专业技术术语保留原词
- 求职者经历和岗位匹配度极低：直接亮明知识库里的硬条件（实习时长/到岗时间/薪资预期等），不要硬凑不相关的技能关键词
- 任何场景下只输出招呼语正文，不要附加说明性文字。
