# BOSS直聘高回复率招呼语生成规则
> 这是一个可复用的生成Skill：根据岗位JD和求职者知识库，生成招聘平台私聊HR的高回复率招呼语。
> 输出文本将通过 `/api/greetings` 写回工作台面板，面板可手动编辑，存储内容为最终事实来源。

## 核心生成铁律（优先级最高）
1. **零礼貌冗余开场**：绝对禁止"您好、看到您发布的岗位、对这个方向很感兴趣、希望获得机会、贵司"这类客套废话，开头第一句直接甩硬货。
2. **前15字黄金位**：开篇前15个字符必须直接抛出和岗位最匹配的核心技能/经历，HR扫一眼就判断是对口候选人，不要把关键词埋在句子中间；哪怕岗位匹配度弱，也要把自己最硬的相关经验放最前面，禁止用"了解XX基础、对方向感兴趣"这类弱表述起手。
3. **开头角度多样化**：不要千篇一律都用"具备XX实战经验"起手，根据岗位场景换不同的动词开头（熟练用XX、独立做过XX、日常用XX提效、有公网上线作品等）；同公司/同岗位类型的多条招呼语，必须换不同的切入角度，不能用相似素材起手，避免重复感——HR同时收到两条几乎一样的打招呼，一眼就看出来是群发的，回复率会直接下降。
4. **硬性痛点精准响应**：只有当JD明确写出"可接受出差、能抗压、能接受加班、外勤驻场"这类硬约束时，才在话里主动对应适配；如果JD只是提到"弹性工作制、不强制加班、周末双休"这类正向福利描述，不要过度表态"我能接受加班、抗压"，反而显得心虚，这类福利不需要专门回应。
5. **真人打字感标点**：分句尽量只用逗号，少用句号；最后一句可以不打标点，像手机上快速打字的自然状态，不要用过于规整的书面标点。
6. **语气统一克制**：招呼语里不要加emoji、不要加感叹号，保持平静实在的语气，不要过度热情，像正常来沟通的在校生，不要写"非常非常希望加入团队！！！"这种一眼假的内容。
7. **全程精简无套话**：删除所有空泛形容词（吃苦耐劳、学习能力强、踏实认真），每一句话都是HR关心的硬信息，总长度控制在80-120字，绝对不超过130字符（BOSS直聊会自动截断）。
8. **全量覆盖更新**：本批次要覆盖所有**已勾选（checked:true）**的岗位，不要留旧版本招呼语不更新；未勾选的岗位不要动。

## 话术骨架（按优先级从前到后排，缺素材的段落直接跳过，不要硬凑）
1. 【开篇优势段（前15字核心位）】：直接上和JD最匹配的技能/经历关键词
2. 【匹配经历段】：围绕JD核心要求，写1条最贴合的实践/项目经历，直接命中JD关键词
3. 【痛点适配段】：对应JD里的硬要求（出差、抗压、出勤节奏等），主动给出适配答复
4. 【硬条件段】：可稳定实习时长、每周可到岗天数，写知识库里真实能提供的最大值，不要主动缩短自降匹配优势
5. 【收尾】：自然结束，不用生硬的固定套话，像真人聊天的收尾即可。

**动词库（按语气强度选，不要吹过头）**：
| 段 | 动词选项 | 约束 |
|---|---|---|
| 技能 | 掌握 / 熟练 / 熟悉 / 了解 | 有完整落地经验用熟练/掌握，做过Demo用熟悉，仅理论认知用了解 |
| 经历 | 做过 / 具备……的实战经验 | 真实完成过的项目才能用"做过" |
| 能力承诺 | 能完成 / 快速上手 / 能 | 对应JD要求的具体能力写 |
| 硬条件 | 可/能稳定实习N个月以上 | N按JD要求的实习时长写即可，用户可自行根据自身情况调整 |
| 特色 | 擅长 | 写具体的业务落地特点，不要写空泛形容词 |

## 经历包装边界
✅ 允许围绕JD关键词，把课程项目、课程作业、自练Demo、相关实践经历往JD方向侧重表述；同一项目根据JD侧重点调整描述，不要罗列多个项目。
✅ 个人身份、专业、技能等信息必须严格照抄知识库原文，不要泛化成模糊表述。
⚠️ **内容来源严格限制**：写进招呼语的所有内容，只能来自三个地方——知识库中正式记录的信息、当前岗位的JD原文、本Skill的生成规则，以及用户在对话中明确授权使用的临时要求。智能体在对话过程中捕捉到的零散记忆、用户随口提到的经历，不能直接写进招呼语；应该先询问用户是否要补充到知识库中，确认后再使用。禁止自作主张把对话中的零散信息直接带入招呼语。
✅ **低门槛通用项灵活规则**：如果JD里出现没有技术壁垒的通用要求——比如Word/Excel/PPT等Office办公软件、写文档/做汇报材料、基础沟通协调、会议记录、资料整理这类在校大学生普遍具备的基础能力，哪怕知识库没有单独记录，也可以直接写上"熟练使用/擅长"这类表述作为兜底。位置根据JD灵活判断：如果这个岗位本身就是行政/运营/文职类，这类通用能力就是核心要求，正常放到前面对应；如果这个岗位的核心是技术类能力，Office/文档类要求只是附带提一句的凑数项，就放在句子后半段一笔带过，不要抢占核心技术/经历的展示位置，也不要把这类内容写的过度强调（比如不要写"精通Office全栈"）。
✅ **项目作品链接规则**：触发条件——当JD明确提到"有相关项目经验优先、附作品集/GitHub/个人链接优先、附作品链接"这类要求时，直接从知识库中取出对应项目链接，写"做过XX项目/作品，链接:XXX"，这类真实作品是展示硬优势的核心素材，放到前面位置匹配JD偏好；如果JD没有提作品/链接要求，就不要主动贴长链接，避免破坏句子流畅度。
❌ 禁止编造和求职者身份严重脱节的内容：比如工作多年全职经验、主导大厂核心项目、精通全栈技术这类一面试就穿帮的内容。
❌ 每条招呼语只服务当前一条JD，两条调换岗位还能通用 = 不合格。

## 红线（出现任意一条即为废稿）
❌ 禁止任何问候语、自我表达兴趣的铺垫句
❌ 禁止空泛套话：吃苦耐劳、学习能力强、性格开朗、踏实肯干
❌ 禁止问句结尾：请问还招人吗、方便聊聊吗
❌ 禁止把能力关键词埋在句子后半段
❌ 禁止摘抄JD大段原文，只提取关键词自然融入句子
❌ 禁止输出解释、思考过程、引号、JSON代码、备注文字，只输出招呼语正文
❌ 禁止超过130字符，超过必须删冗余套话压缩

## 参考范例
### 正向标杆（持续用真实高回复率案例替换）
> 具备Agent流程设计与Prompt调优实战经验，做过AI Demo、MVP原型和PRD撰写，熟悉RAG、Workflow相关概念，可整理竞品与客户反馈，能稳定实习6个月，擅长从业务场景落地AI Skill资产建设

### 反面坏例（禁止生成）
> ❌您好，我看到咱们在招测试实习生，我对这个岗位很感兴趣，我学习能力强能吃苦耐劳，请问方便聊聊吗？
> （全是礼貌废话，前15字无任何优势，没提任何岗位匹配点，没覆盖痛点）

## 边界情况处理
- JD内容很短、有效关键词少：基于岗位名称+可迁移通用能力，优先把实习时长、时间灵活性、可适配加班/出差这几个HR最关心的硬条件放前面
- JD中英混合或纯英文：招呼语统一用中文写，专业技术术语保留原词
- 求职者经历和岗位匹配度极低：直接亮明实习时长、时间灵活性、可接受出差/加班的适配性，不要硬凑不相关的技能关键词
- 任何场景下只输出招呼语正文，不要附加说明性文字。

## 写回工具（面板实时刷新）
```
POST http://127.0.0.1:7788/api/greetings
Content-Type: application/json; charset=utf-8

{ "items": [ { "url": "<岗位 url>", "greeting": "<招呼语正文>" }, ... ] }
```
- 响应：`{ "ok": true, "updated": N }`；面板表格实时刷新，不用重载
